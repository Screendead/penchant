Shared fixes

  • Trends chips wrap onto a second row in the pane. No more clipping. The phone sheet keeps its scrolling row.
  • The chart takes the pane's spare height, from 220 to 640 pt.
  • The Log button sits under the last tally instead of at the foot of the column.
  • Synced moves onto the Trends title row.

A · Letterboxed canvas

Once the window is larger than 1320×860, the app sits centred at that size as a framed card on a slightly lighter backdrop. It always looks like the well-proportioned default window.

EffortSmallest. One wrapper in Homepage that sets the canvas as the layout's screen size.
CostA fullscreen Mac shows about 45% of its area as backdrop. With many habits the list still scrolls inside the canvas, and the Log button scrolls with it.
RiskLow. A card inside a fullscreen window can look like a web page, not a Mac app. Menus and dialogs still open relative to the real window.

B · Responsive scaling

Two panes that grow with the window. The dial grows with the window's height, to 44%. Today's column takes 36% of the width, up to 760 pt. Trends widens to 1100 pt and the chart fills the height.

EffortSmall to medium. The dial's geometry is fixed at 320 pt, so the larger dial is that dial scaled up. Its labels and beads grow with it.
CostThe scaled dial's type gets big (the clock is about 36 pt at 550 pt). At 1200×780 Today's column is narrower than on master (432 pt instead of 504 pt), so the decided default changes a little. Retuning the ratio removes that.
RiskLow to medium. It behaves the same at every size, so there is no breakpoint to jump across. A 2000 pt chart spreads 30 days thin.

C · Three columns from 1600 pt

From 1600 pt wide the window splits into three columns: the dial, a Habits column with the tallies and the Log button, and Trends. The dial fills its column's height. Below 1600 pt it is today's split view.

EffortMedium to large. It is a third layout to keep in step with the other two (keys, focus, snackbar clearance, guest and recovery banners, e2e at 1600+).
CostWith a few habits, the Habits column is mostly empty below the list. The layout jumps when the window crosses 1600 pt.
RiskMedium. It uses big screens best and reads most like a desktop app, but it is the most code that only Mac fullscreen users see.
Recommendation

B, responsive scaling

  • It fixes every complaint with one rule and no breakpoint. The window fills at any size, and you get the same layout as you resize.
  • The code is small and stays close to the split view that already shipped, so 1g's e2e rewrite and the macOS keys need no new layout.
  • A wastes the screen Jack fullscreened for. C costs a third layout for the one size where B already looks right.
  • Before it merges: cap the dial near 480 pt, and keep Today's column at 504 pt at 1200×780 so the decided default stays as it is.
